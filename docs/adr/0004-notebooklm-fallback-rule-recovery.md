# ADR-0004: 補回 4 個分析型技能遺失的「NotebookLM 研究遵從指示」鐵律

- Status: Accepted
- Date: 2026-08-11

## Context

在階段一審計 `financial-analyst`、`investment-researcher`、`tech-analyzer`、
`pe-river-map` 這 4 個技能時，發現一段名為「全域鐵律：NotebookLM 研究遵從指示」
的 `[WARNING]` 規則，**只存在於 `Archive` 封存版，現行版全部遺失**：

> 1. 當任務指示「透過 NotebookLM 進行研究/查詢」時，必須嚴格呼叫 `notebooklm`
>    相關 MCP 工具。
> 2. 若遇到無法連線、憑證過期（`auth_status: stale` 或 `Authentication expired`）
>    等錯誤時，**絕對禁止**未經同意自行改用常規網路搜尋或其他工具替代。
> 3. 遇到錯誤時，請**立刻中斷動作並主動告知使用者**，請使用者協助登入或修復連線後，
>    再繼續研究任務。

初步 diff 分析（用行數統計 + 摘要判斷）沒有抓到這個遺失，是透過人工要求逐字核對
4 個技能全文才發現的。推測遺失原因：現行版經歷過一輪全域的繁體中文在地化用詞修正
（`宣告`→`聲明`、`透過`→`通過`等），這條規則很可能在那次批次修改中被誤刪，而不是
刻意捨棄的舊架構殘留——因為同一段文字在 Archive 版本裡是完整存在的，且內容本身
沒有過時的技術債痕跡（不像 `csv-data-summarizer` 那個 Archive 版的「記憶編譯器」
概念，一看就是舊架構產物）。

## Decision

1. 這 4 個技能正式遷移進 `HH.AI_v2` 時，把這段 WARNING 規則從 Archive 版本
   搬回最終版本，內容保持原文不變。
2. 這條規則背後的原則——**「指定的資料來源失效時，不能悄悄換成其他工具頂替，
   必須停下來明確告知使用者」**——具有超越這 4 個技能的普適性，尤其呼應
   `system_status_report.md` 記錄的 8/6 NotebookLM 認證問題（Google DBSC 攔截）。
   往後任何技能只要依賴特定的資料來源工具（不限 NotebookLM），都應該遵循同樣的
   「失效即停、不悄悄替代」原則，不需要每個技能各自重複寫一次，但遷移時如果
   遇到類似規則，比照這次的方式：**先假設它是刻意設計、值得保留，而不是預設
   為舊架構雜訊**。

## Consequences

- 往後審計技能時，不能只依賴自動化 diff 的行數統計/摘要做判斷，重要的技能
  （尤其牽涉外部工具呼叫、資料來源可信度的技能）要在合併/取捨前逐字讀過全文，
  這次的方法（要求 Agent「不要只看 diff 摘要，要實際讀過雙方全文」）證明有效，
  往後審計類似情況直接沿用這個做法。
- 增加了階段一審計的工作量（逐字核對比單看 diff 摘要慢），但避免了在重構過程中
  無聲遺失重要的安全規則——這正是根目錄 `AGENTS.md` 第 0 節「知識保存優於檔案
  保存」原則在實務上的具體案例。
